# Uber Model Project

### 📌 Project Overview
This project demonstrates a production-grade, real-time data engineering solution built on Azure. 
It simulates a ride-confirmation system (similar to Uber or Ola) where events are generated by a web application and processed through a Medallion Architecture (Bronze, Silver, and Gold layers).
The core focus of this project is on modern data engineering practices, including Metadata-Driven Pipelines, Spark Declarative Pipelines (SDP), and Real-Time Streaming using the Publisher-Subscriber (Pub/Sub) model


--------------------------------------------------------------------------------

### 🛠️ Tech Stack & Tools
##### Source Systems: 

Custom Web Application (Fast API) & GitHub API

##### Ingestion & Streaming:

Azure Event Hub: Managed Apache Kafka instance for real-time event streaming

Azure Data Factory (ADF): Metadata-driven dynamic ingestion pipelines for bulk/static data

Data Lake: Azure Data Lake Storage (ADLS) Gen2 for hierarchical data storage

##### Processing & Transformation:
Azure Databricks: Using PySpark and Spark Structured Streaming

Spark Declarative Pipelines (SDP): The modern upgrade to Apache Spark for declarative data processing

Jinja2 Templating: For building modular, metadata-driven SQL queries

##### Data Modeling:

Star Schema with SCD Type 2 (Slowly Changing Dimensions) using Auto-CDC


--------------------------------------------------------------------------------
### 🏗️ Project Architecture

The project follows a robust multi-layered architecture:

##### Ingestion Layer:

Real-Time: A Fast API web app sends ride confirmation events to Azure Event Hub

Bulk/Historical: Azure Data Factory performs a "Lift and Shift" of historical and mapping data from GitHub to the Bronze layer in ADLS Gen2

##### Bronze Layer (Raw):

Stores an exact replica of source data in its raw format (JSON)

Captures streaming events from Event Hub and bulk data from ADF

##### Silver Layer (One Big Table - OBT):

Normalization: Binary data from Event Hub is decoded and parsed into a structured format

Jinja2 Magic: Uses a metadata-driven approach with Jinja2 templates to join the streaming table with multiple mapping tables (cities, vehicles, payments) without hardcoding

Streaming Joins: Implements stateful transformations with Watermarking to handle late-arriving data

##### Gold Layer (Analytical):

Star Schema: Transforms the OBT into a curated data model consisting of one Fact Table and six Dimension Tables (Passenger, Driver, Vehicle, Payment, Location, and Booking)

SCD Type 2: Implements Slowly Changing Dimensions for location data, tracking history using start_at and end_at timestamps
